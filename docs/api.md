# HTTP API

Базовый путь — `/api`. Все команды POST и PATCH принимают JSON-объект с заголовком `Content-Type: application/json`. Максимальный размер тела — 32 КиБ. Браузер отправляет запросы на тот же origin. Консольный клиент сохраняет сессионную cookie между запросами. Временные отметки в JSON представлены миллисекундами Unix.

## Сеанс и справочники

| Метод и путь | Доступ | Ответ или тело команды |
| --- | --- | --- |
| `GET /health` | Все | `{"status":"ok"}` после обращения к SQLite |
| `GET /session` | Все | Режим, текущий пользователь или null, названия ролей и доступные демопрофили |
| `POST /session/demo` | Деморежим | `{"profileId":3}`. Устанавливает сессионную cookie |
| `POST /session/login` | Рабочий режим | `{"email":"user@example.org","password":"…"}`. Устанавливает сессионную cookie |
| `POST /session/logout` | Все | `{}`. Отзывает сессию и очищает cookie |
| `GET /catalog` | После входа | Услуги с полями `id`, `name`, `description`, `icon`, `baseHours` и словари статусов и приоритетов |
| `GET /agents` | Координатор | Массив `agents` с идентификаторами, именами и подразделениями специалистов |

Доступные для выбора демопрофили возвращает `GET /session`. В примерах ниже профиль 3 принадлежит сотруднику, 2 — специалисту, 1 — координатору. Cookie-файл в примере хранится во временной папке текущей оболочки.

```sh
curl -s -c /tmp/gosdesk-demo.cookies -H 'Content-Type: application/json' \
  -d '{"profileId":3}' http://127.0.0.1:3000/api/session/demo
curl -s -b /tmp/gosdesk-demo.cookies http://127.0.0.1:3000/api/catalog
```

## Регистрация обращения

`POST /tickets` создаёт карточку и событие регистрации в одной транзакции. Сервер заполняет номер, автора, статус, срок и версию. Начальная версия равна 1.

```json
{
  "serviceId": "signature",
  "priority": "high",
  "subject": "Продлить сертификат отдела",
  "description": "Нужен действующий сертификат для подписания исходящих ответов.",
  "requestKey": "d8728de1072c4598a873e78ac496f698"
}
```

| Поле | Правило |
| --- | --- |
| `serviceId` | Идентификатор услуги из каталога |
| `priority` | `low`, `normal` или `high` |
| `subject` | От 5 до 150 символов после удаления крайних пробелов |
| `description` | От 10 до 4000 символов после удаления крайних пробелов |
| `requestKey` | Необязательный ключ повторной отправки. От 16 до 80 латинских букв, цифр, дефисов или подчёркиваний. Область уникальности — один заявитель |

Успешный ответ `201` содержит поля `ticket`, `events` и `actions`. При повторе с тем же ключом и исходными полями API возвращает актуальное состояние той же карточки.

## Реестр и выгрузка

`GET /tickets` возвращает `items`, `total`, `page` и `pageSize`. Порядок — от новых к старым, при одинаковом времени регистрации первым идёт больший номер. Размер страницы — 10. Пустой результат находится на странице 1, а слишком большой номер страницы приводится к последней доступной.

| Параметр | Значения |
| --- | --- |
| `q` | Часть темы, имени заявителя или подразделения, либо точный номер вида `ГД-1041`, `#1041`, `1041`. Строчные и прописные буквы кириллицы дают одинаковый результат |
| `status` | `new`, `in_progress`, `waiting`, `resolved`, `closed` |
| `priority` | `low`, `normal`, `high` |
| `service` | Идентификатор услуги |
| `active` | `1` включает только новые, находящиеся в работе и ожидающие ответа заявки |
| `assignee` | `mine` для моих назначений, `unassigned` для свободной очереди |
| `deadline` | `overdue` для просроченных, `soon` для активных заявок со сроком в следующие 24 часа |
| `page` | Положительное целое число |

Пример отбора — `GET /api/tickets?active=1&priority=high&service=signature`.

`GET /export.csv` применяет те же фильтры и область видимости ко всем подходящим строкам. Формат — UTF-8 с BOM, разделитель — точка с запятой, даты — ISO 8601 в UTC. Кавычки экранируются. Потенциальные формулы записываются как текст.

## Карточка и изменения

`GET /tickets/{id}` возвращает три объекта данных.

- **ticket** содержит номер, тему, описание, идентификаторы и имена заявителя и исполнителя, подразделение заявителя, услугу, статус, приоритет, версию и даты. Поле `deadlineState` принимает значения `on_time`, `soon`, `overdue`, `met` или `missed`.
- **events** перечисляет события по времени и номеру. У события есть `id`, `at`, `kind`, `actorName` и `detail`.
- **actions** содержит флаги `claim`, `assign`, `comment` и массив доступных целевых статусов `transitions`.

Каждая команда использует текущую целочисленную версию карточки. Успешное изменение возвращает обновлённую карточку, историю и список действий.

| Действие | Метод и путь | Пример тела |
| --- | --- | --- |
| Взять свободную заявку | `PATCH /tickets/{id}` | `{"action":"claim","version":1}` |
| Назначить специалиста | `PATCH /tickets/{id}` | `{"action":"assign","assigneeId":2,"version":1}` |
| Запросить уточнение | `PATCH /tickets/{id}` | `{"action":"transition","status":"waiting","note":"Уточните кабинет.","version":2}` |
| Вернуть в работу | `PATCH /tickets/{id}` | `{"action":"transition","status":"in_progress","note":"Кабинет 24.","version":3}` |
| Предложить решение | `PATCH /tickets/{id}` | `{"action":"transition","status":"resolved","note":"Сертификат продлён.","version":4}` |
| Подтвердить решение | `PATCH /tickets/{id}` | `{"action":"transition","status":"closed","version":5}` |
| Добавить комментарий | `POST /tickets/{id}/comments` | `{"body":"Результат проверен.","version":5}` |

Пояснение обязательно при переходе в ожидание, предложении решения, возврате из решённых и ответе заявителя на запрос уточнения. Минимум обязательного пояснения — 3 символа, максимальная длина — 2000. Комментарий принимает от 1 до 2000 символов. Полная таблица переходов находится в [описании жизненного цикла](architecture.md).

## Отчёт

`GET /summary?days=7` принимает значения 7, 14 и 30. Для каждого профиля учитываются доступные ему заявки.

| Поле | Содержимое |
| --- | --- |
| `days`, `start`, `asOf` | Период, начало первого дня UTC и момент расчёта |
| `counters` | Активные, неназначенные, просроченные на момент расчёта, а также поступившие, решённые и решённые в срок за период |
| `daily` | По одной записи с `at`, `created`, `resolved` для каждого дня, включая дни с нулём событий |
| `services`, `distribution` | Число активных заявок по услугам и статусам |
| `departments` | Поступления по подразделениям за период |
| `attention` | До пяти самых срочных активных заявок с истёкшим или близким сроком |

## Ошибки

Ответ содержит машинное поле `error` и русскоязычное `message`.

| HTTP | Причина |
| --- | --- |
| 400, 413, 415 | Некорректный JSON, превышен размер тела или неверный тип содержимого |
| 401 | Требуется вход или неверны учётные данные |
| 403 | Действие запрещено для роли, статуса или origin |
| 404 | Маршрут или доступная пользователю карточка отсутствует |
| 409 | `version_conflict` требует перечитать карточку. `request_key_conflict` означает, что ключ регистрации уже связан с другим содержимым |
| 422 | Ошибка формата, неизвестное значение или обязательное пояснение отсутствует |
| 429 | Достигнут предел попыток входа |
